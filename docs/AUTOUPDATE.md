# Обновление программы Hot Watcher

Проверка VLESS-подписки каждые 1800 секунд остаётся отдельной функцией. Обновлятор программы проверяет подписанные GitHub Releases каждые 6 часов с задержкой до 15 минут и не вызывает `xkeen`, не меняет Xray или конфигурацию подписки. Программа обновляется только из raw asset для текущей архитектуры.

Первый переход с 0.1.0 выполняется вручную через offline archive и `install.sh` при остановленной службе: старый процесс не знает maintenance protocol. Новая установка начинает с `mode=notify`; сама программа при этом не заменяется. Чтобы включить автоматическую установку patch в текущей minor-ветке:

```sh
/opt/sbin/hotwatcher update enable
/opt/sbin/hotwatcher update status
```

`enable --notify` оставляет только проверки. `disable` прекращает проверки программы, `pause on|off` откладывает её замену, `pin VERSION` ограничивает выбранную версию. `hold on` из Hot Watcher также откладывает установку. Эти действия не отменяют расписание подписки. Для ручного обновления достаточно `hotwatcher update`: команда показывает установленную и доступную версии, затрагиваемую службу и ход операции, затем проверяет релиз, скачивает пакет и применяет его. `update status` показывает краткое состояние, последний результат и автоматический откат; прежний машинный отчёт доступен через `update status --json`. `check`, `download` и `apply` доступны отдельно. Все пути проверяют подпись и хеш.

Установленный updater `v0.2.4` отклоняет обычные поля `url` в ответе GitHub Releases.
Если `hotwatcher update status` работает, а `hotwatcher update check` отвечает
`json: unknown field "url"`, обычный `apply` тоже остановится до скачивания.
После публикации подписанного `v0.2.6` выполните
одноразовый bootstrap-ремонт: распакуйте архив из GitHub Release в
`/opt/tmp/xkeen-hot-watcher`, затем выполните:

```sh
cd /opt/tmp/xkeen-hot-watcher
sh scripts/repair-updater.sh
/opt/sbin/hotwatcher update status
/opt/sbin/hotwatcher update check
/opt/sbin/hotwatcher url migrate
xkeen -xtest
/opt/sbin/hotwatcher sync
/opt/sbin/hotwatcher keys
```

Скрипт проверяет `dist/SHA256SUMS` из пакета, сохраняет старые бинарники для отката,
заменяет Hot Watcher и updater и перезапускает только их службы. Xray не трогается.
Этот разовый путь доверяет скачанному с GitHub архиву как при первоначальном
`install.sh`; подписанный manifest отдельно проверяется обычным updater при
последующих обновлениях. Если `update status` тоже выдаёт `unknown field "url"`,
сначала исправьте `/opt/etc/hotwatcher/updates.json`: поле `url` ему не принадлежит.

После такого ремонта следующие подписанные patch-релизы устанавливаются обычными
`update check` и `update apply`:

```sh
/opt/sbin/hotwatcher update status
/opt/sbin/hotwatcher update
/opt/sbin/hotwatcher version --json
/opt/sbin/hotwatcher status
```

`apply` самостоятельно скачает raw ARM64 asset, проверит подпись и хеш и заменит
только бинарник Hot Watcher. Повторять `install.sh` для этого обновления не нужно.
`url migrate` сохранит текущую ссылку из старого приватного файла в
`07_hotwatcher_api.json`, сохранив объект Xray API. Старый файл остаётся приватной
копией для установленного updater; не удаляй его.
Для автоматического выбора узла после обновления нужно завершить `adopt` и включить
Hot Watcher по инструкции в README. Если служба включена, updater проверит готовность
нового процесса и при её отсутствии вернёт старую программу.

После автоматического отката тот же asset не пробуется повторно по таймеру. Администратор может сознательно разрешить новую попытку командой `hotwatcher update retry`; подпись, хеш и совместимость проверяются заново. `pin` сам по себе запрещает автоматическую замену.

Конфигурация хранится отдельно в `/opt/etc/hotwatcher/updates.json`. Подписанный asset должен содержать ту же версию, commit и архитектуру в `version --json`. Новый процесс сначала проходит read-only preflight и validation heartbeat, затем штатная служба подтверждает готовность. При ошибке предыдущий бинарник возвращается атомарно. Установленная и последняя проверенная предыдущая версия сохраняются в `/opt/var/lib/hotwatcher-updater/versions`.

Сейчас `apply_window` поддерживается только как `null`. Реальное окно времени требует отдельного подтверждения доступности IANA timezone на Entware. Telegram и автоматическое обновление самого updater не входят в protocol v1. Если будущий релиз потребует более нового updater или миграции схемы, он не применяется автоматически.

Запуск после обновления использует сохранённый deadline следующей проверки подписки, поэтому обновление программы не запускает немедленную ротацию ключей. Первый cold start без сохранённого deadline по-прежнему проверяет подписку сразу.
