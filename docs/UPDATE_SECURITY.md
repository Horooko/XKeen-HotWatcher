# Границы доверия updater

Updater доверяет только закреплённому Ed25519-ключу. Подпись проверяется над точными байтами manifest с контекстом приложения, до запуска candidate. Затем проверяются repository ID, tag, версия, политика, архитектура, размер и SHA-256 raw asset. Неизвестные JSON-поля, duplicate keys, trailing JSON, неподходящие пути и HTTP redirect отвергаются. TLS verification не отключается, GitHub token на роутере не хранится.

`update.lock` сериализует установки, `maintenance.json` запрещает новые пишущие операции Hot Watcher, а прежняя subscription lock завершает уже начатые операции. `pending.json` подписки и `hold` блокируют применение. Updater не вызывает команды XKeen/Xray и не меняет firewall, routing, выбранный сервер, URL подписки или state подписки.

Основной Xray проверяется по PID, starttime, executable и хешу cmdline до и после установки. Внешний restart Xray или изменение защищённой конфигурации приводит к откату новой программы и отдельной ошибке. Это проверка результата установки, а не гарантия сохранности каждой будущей TCP/UDP-сессии. Проверка на реальном роутере и Destiny 2 остаётся обязательной для таких эксплуатационных выводов.

Компрометация приватного signing seed позволяет подписать вредный релиз. Ротация ключа и updater v2 требуют контролируемого нового bootstrap; updater не принимает новый ключ из того же непроверенного релиза. Доступ к root на устройстве также позволяет подменить установленную программу и локальные файлы, чего подпись GitHub asset сама по себе не предотвращает.
