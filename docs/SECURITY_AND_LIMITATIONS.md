# Безопасность и ограничения

## Это не kill-switch и не обещание «никогда не покажет основной IP»

Hot Watcher убирает вызов полного рестарта из **своего** пути обновления подписки.
Если Xray будет остановлен другой задачей, аварийно завершится, роутер снимет правила
перехвата или трафик не соответствует твоим proxy-правилам, прямой WAN всё ещё возможен.
Параметр routing `fallbackTag` внутри Xray также не заменяет независимый firewall.

Надёжный fail-closed для устройства/VLAN — отдельная политика firewall, учитывающая
твою конкретную схему Keenetic, IPv4/IPv6, direct-исключения, DNS и работу netfilter hooks.
Этот проект **намеренно не ставит универсальные iptables DROP-правила**: без схемы
интерфейсов они способны отрезать управление роутером/обычный LAN.

Проверяющий IP сайт может идти `direct` по исходным правилам — смена результата этого
сайта сама по себе не доказывает, каким маршрутом идёт игровая сессия.

## Игры, UDP и внешний IP

Старые outbounds остаются в памяти; процесс и transparent-proxy rules не перезапускаются
Hot Watcher-ом. Это уменьшает число причин разрыва, но не гарантирует сессию Destiny 2.

Игра может создавать дополнительные TCP/UDP-потоки посреди активности. Они после смены
выбранного сервера получат новый маршрут и, возможно, другой внешний IP, хотя старый
поток не закрывался. Также влияют UDP idle timeout/NAT, политика сервера, истечение
учётных данных, изменения адреса VPS и особенности Mux/XUDP конкретного Xray.

30 минут grace — не доказательство, что все старые сессии завершились. Поэтому
автоматическая очистка выключена. `hold on` останавливает обновления и GC, однако
не может продлить действительность старого UUID у провайдера. Координированная ротация
со временем одновременной работы старого и нового ключа предпочтительнее мгновенного отзыва.

HTTPS probe подтверждает доступность HTTP 204 через узел, но не UDP/игровую доступность.
В ходе подготовки проекта реальная игровая сессия не тестировалась.

## API и секреты

API Xray не предоставляет в этой схеме авторизацию приложения. Он слушает только
loopback, приложение отклоняет non-loopback `api_address`. Не публикуй этот порт через
reverse proxy, SSH forwarding для посторонних, LAN/WAN port forward или WebUI без защиты.
Другие процессы на роутере с доступом к localhost смогут обращаться к API.

URL подписки, UUID, state, pending transaction, pre-migration backup и резервный crontab
являются секретами. Основной URL теперь находится в
`/opt/etc/xray/configs/07_hotwatcher_api.json` с правами `600`; приватная копия для
старого updater — в каталоге `700`. **Это не шифрование диска.** Root/администратор
хранилища всё равно может их прочитать. Не публикуй API-фрагмент в issue, PR или логи.

Программа не пишет URL подписки, тело ответа или полный stdout/stderr Xray API в логи.
`lso` может содержать учётные данные; его ответ разбирается в памяти и не публикуется.
Имена узлов выводятся только отдельной командой `nodes`; URL-подобные имена скрываются.
Обработанные ошибки конвертации содержат номер строки, но не её содержимое.

Файл URL не попадает в аргументы запуска curl/Xray: HTTPS загружает сама программа.
HTTP_PROXY/HTTPS_PROXY из окружения не используются для загрузки подписки. При
необходимости доступа к источнику через прокси это нужно проектировать отдельно.

## Доверие к подписке

Используй контролируемого провайдера и HTTPS. Токен может давать доступ к платным узлам;
при его публичной публикации перевыпусти токен. Из чужой подписки принимается только
ограниченный набор URI-параметров VLESS, а не произвольные локальные файлы или shell.
Адреса серверов всё ещё задаёт провайдер: endpoint может быть частным адресом/DNS-именем.
Защита от любого сценария SSRF/враждебного root-процесса здесь не заявляется.

## Эксплуатационная граница

Один updater — один generated_file и balancer. Другой updater или ручное изменение файла
нарушает контракт владения. Хеш-проверка обнаруживает уже произошедшее изменение, но
не даёт межпрограммной транзакционной блокировки для постороннего приложения.

Нужно свободное место под state, временные конфиги и несколько копий списка узлов.
Во время проверки кандидата временно запускается дополнительный Xray. Потребление
памяти на конкретной модели роутера не измерено; на маломощном устройстве начни с малого
числа узлов и следи за RAM. Обновления последовательные, не параллельные.

Старая исполняемая программа watcher не опасна сама по себе, если не запущена. Опасен
её параллельный запуск/cron на тот же файл. Бинарник можно удалить после проверки новой
схемы, не удаляя сохранённый конфиг действующего Xray.
