# Откат и восстановление

## 1. Незавершённая транзакция

```sh
hotwatcher status
```

Если `pending_transaction: true`, обычный sync заблокирован намеренно.

**Завершить начатую замену:**

```sh
hotwatcher recover
```

Повторно проверяется выбранный candidate, недостающие новые outbounds добавляются,
подтверждается pin, записываются файл/state. Затем журнал удаляется. Если сервер/ключ
по-прежнему не работает, операция останавливается без принудительного рестарта.

**Вернуться к конфигурации до этой попытки:**

```sh
hotwatcher abort
```

Возвращаются предыдущие target и файл/state. Добавленные в этой попытке handlers
сохраняются в памяти ради возможных соединений; это не полная очистка heap. После будущего
планового рестарта они не будут загружены из восстановленного файла.

`recover` и `abort` — альтернативы. Нельзя выполнять обе подряд как обязательную цепочку.
При внешней ручной правке файла обе команды откажутся перезаписывать неизвестный вариант.

## 2. Полностью вернуться к исходному subscription-watcher

Это обслуживание **вне игры**. Оно может потребовать restart и разорвать сессии.

1. Отключить и остановить только Hot Watcher:

```sh
rm -f /opt/etc/hotwatcher/enabled
/opt/etc/init.d/S99hotwatcher stop
```

2. Убедиться, что существует оригинальная резервная копия:

```sh
ls -l /opt/var/lib/hotwatcher/pre-migration-outbounds.json
```

3. Скопировать её в рабочий путь, сохранив текущий вариант отдельно:

```sh
cp /opt/etc/xray/configs/04_outbounds.main.json /opt/var/lib/hotwatcher/outbounds-before-offline-rollback.json
chmod 600 /opt/var/lib/hotwatcher/outbounds-before-offline-rollback.json
cp /opt/var/lib/hotwatcher/pre-migration-outbounds.json /opt/etc/xray/configs/04_outbounds.main.json
chmod 600 /opt/etc/xray/configs/04_outbounds.main.json
xkeen -xtest
```

4. Если конфиг валиден, вне игры:

```sh
xkeen -restart
xkeen -status
```

Старый JSON может содержать **уже отозванные** ключи. Успешный config test этого не
проверяет. При необходимости получить свежую подписку старым watcher до запуска.
Старый `04_outbounds.json` с отдельным `vless-reality` остаётся дополнительным резервом,
но маршрутизация должна явно на него ссылаться, чтобы он использовался.

5. При необходимости восстановить cron из нужного приватного backup. Сначала выбрать
конкретный файл по времени и проверить, что в нём нет лишних старых задач:

```sh
ls -l /opt/var/lib/hotwatcher/crontab-before-hotwatcher-*.txt
# Затем применить выбранный файл, а не шаблон со звёздочкой:
# crontab /opt/var/lib/hotwatcher/crontab-before-hotwatcher-YYYYMMDD-HHMMSS.txt
```

Не запускай Hot Watcher с прежним state после этого: его hash согласован с другой
конфигурацией. Для новой миграции сохрани старый приватный каталог state отдельно,
создай чистый `state_dir` с правами 700 и заново выполни `adopt`.

## 3. Удалить только новую программу

```sh
sh scripts/uninstall-program.sh
```

Скрипт останавливает новую службу и удаляет только её бинарник/init-скрипт. Рабочий
Xray, его JSON, API fragment и секретные данные сохраняются. Это не полный миграционный
откат и не удаление ключей с диска. После перехода на другую схему секретные резервные
копии нужно отдельно удалить согласно своей политике хранения.

Никогда не удаляй `pending.json` просто для подавления ошибки: он может быть единственной
записью, связывающей уже изменённый runtime с ещё старым файлом на диске.
