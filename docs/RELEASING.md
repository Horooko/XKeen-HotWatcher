# Выпуск подписанного релиза

Публичный ключ bootstrap v1 записан в `release-public-key.txt` и закреплён в `internal/updater/update.go`. Локальный seed создан в `.git/update-signing-seed.b64`; он **не отслеживается Git**. Для GitHub Actions maintainer должен сохранить его значение как environment secret `UPDATE_SIGNING_SEED` в защищённом environment `signed-release`. Перед публикацией workflow проверит, что подпись соответствует закреплённому публичному ключу; неверный secret остановит job. Не добавляйте seed в commit, PR или логи.

После объединения изменений в `master` откройте GitHub → Releases → Draft a new release. В поле **Tag** введите `vMAJOR.MINOR.PATCH` и выберите **Create new tag ... on publish**; в **Target** выберите `master`. Поле Release title не создаёт tag. Нажмите **Publish release**. Событие `release.published` запустит `.github/workflows/release.yml`: он проверит environment secret и соответствие seed закреплённому ключу, выполнит тесты/vet, соберёт arm64/amd64 assets, создаст и подпишет manifest, приложит файлы к созданному Release, скачает их обратно и проверит SHA256SUMS. Пока job работает, Release виден без установочных файлов; updater пропустит его до появления подписанного manifest. Проверьте успешное завершение job и наличие assets перед установкой.

**Отключите immutable releases** в настройках GitHub до публикации: GitHub не разрешает прикладывать assets к уже опубликованному immutable Release. `Save draft` также не запускает сборку: для draft-событий GitHub не запускает `release.created`, а новый tag из этого меню создаётся при публикации. Защитите tag/environment. Не повторно используйте существующий номер версии с другими байтами. Если job упал до загрузки файлов, после исправления причины запустите `signed-release` через Actions → Run workflow с тем же tag; повтор возможен только для опубликованного Release без загруженных assets.

Для установленной версии 0.2.x автоматический кандидат должен быть более новым patch той же minor-ветки; после подписанного `v0.2.10` следующим кандидатом будет `v0.2.11`. Major/minor и prerelease автоматическая patch-policy откладывает. Raw asset `hotwatcher_vX.Y.Z_linux_arm64` используется для updater; tar.gz предназначен для bootstrap installation. Секреты роутера в release assets не входят.

Пустые `v0.2.0` и `v0.2.1` не являются установочными релизами: у них нет подписанного manifest и бинарников. `v0.2.3` — первый подписанный релиз с ARM64-архивом. Версия текущего исходного кода — `0.2.11`; после объединения PR в `master` для подписанного выпуска нужен новый тег `v0.2.11`. Создание тега на ветке PR не запустит корректную публикацию из `master`. Повторная публикация старого номера версии не обновит установленную программу.
