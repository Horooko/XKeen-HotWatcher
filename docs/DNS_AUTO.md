# Автоматический выбор DNS в Xray

`hotwatcher dns auto on` настраивает **встроенный DNS-модуль Xray**. Hot Watcher трижды запрашивает каждый выбранный IP-адресный DoH с прямого маршрута роутера и требует хотя бы два полноценных DNS-ответа с публичным IPv4-адресом. При включённом автоподборе он выбирает до трёх самых быстрых ответивших адресов по медианной задержке, проверяет подготовленный DNS во временном Xray и только после этого записывает файл. Если ответили менее двух адресов, файл не меняется. Xray параллельно обращается к выбранным серверам и использует первый успешный ответ. Режим `https+local` обходит маршрутизацию Xray через VLESS, а IP-адреса DoH не требуют системного DNS для установления соединения. Эти проверки не подтверждают, что правила перехвата трафика роутера работают для устройств LAN.

## Каталог адресов в Web UI

Редактируемое текстовое поле содержит **все DNS-адреса с предоставленных скриншотов**: AliDNS, DNSPod, Cloudflare, Google, TrafficRoute, OpenDNS, Yandex, Comodo, AdGuard, а также Local и DHCP. Адрес без `#` участвует в проверке; строка с `#` исключена. Выбор сохраняется после проверки. Список ограничен известными адресами каталога: произвольный адрес, повтор или несовместимый адрес в активной строке отклоняется с объяснением. Яндекс исключён по умолчанию, но поддерживаемый IP DoH можно включить явно.

**DNS auto выбирает только поддерживаемые IP-адресные DoH.** В каталоге показаны и другие адреса, но наличие строки не делает протокол пригодным для текущего DNS auto: UDP входит в маршрутизацию Xray и может создать петлю прозрачного прокси; `tls://` (DoT) и `h3://` не являются поддерживаемыми адресами DNS-сервера Xray; DoQ пока не проходит полноценную проверку Hot Watcher. Доменный адрес `https+local` зависит от системного DNS роутера и также может замкнуть маршрут. Такие строки оставлены закомментированными для справки. Поддерживаемые альтернативные IP DoH из скриншотов, включая `1.0.0.1`, `8.8.4.4`, `223.6.6.6` и `120.53.53.53`, доступны для автоотбора наряду с исходными адресами. Снять флажок автоматического выбора можно в Web UI: тогда в конфигурацию попадут все отмеченные адреса, которые успешно ответили, вместо трёх лучших.

Это **не меняет DNS-настройки Keenetic, DHCP или Karing**. Функция влияет на запросы, которые уже направлены во встроенный DNS Xray. Если устройства используют DNS роутера напрямую, этот режим сам по себе их запросы не перенаправит. Параллельный запрос отправляется нескольким выбранным серверам: это ускоряет выбор ответа, но каждый из них может видеть запрашиваемое имя. Режим `https+local` **обходит `routing` и не использует `dns.tag`**. Если существующий `dns.tag` указан в правиле `inboundTag`, автоматическое изменение отклоняется без записи файла: это была бы незаметная замена DNS-over-VLESS на прямой DoH. Проба `dns test` идёт непосредственно с роутера.

Пример с `"tag":"dns-in"`, `"servers":["8.8.8.8"]` и `"queryStrategy":"UseIP"` из [статьи XKeen](https://jameszero.net/3398.htm) описывает **другую схему**: DNS-трафик направляется через VLESS дополнительными правилами `routing` и DNS outbound. Один только объект `dns` её не включает. В создаваемом Hot Watcher фрагменте `queryStrategy` явно устанавливается в `UseIP` (стандартное значение Xray); существующее значение не меняется.

## Включение

В Entware shell вне игровой сессии:

```sh
/opt/sbin/hotwatcher dns status
/opt/sbin/hotwatcher dns test
/opt/sbin/hotwatcher dns auto on
xkeen -xtest
xkeen -restart
xkeen -status
/opt/sbin/hotwatcher dns verify
/opt/sbin/hotwatcher dns status
```

`dns auto on` меняет файл в `/opt/etc/xray/configs` только после успешной проверки **полного набора фрагментов** установленным Xray. Если исходный `02_dns.json` содержит только комментарий и не содержит объекта `dns`, он остаётся без изменений: Hot Watcher создаёт отдельный `/opt/etc/xray/configs/02_hotwatcher_dns.json`. Если объект `dns` уже есть в одном из фрагментов, он меняется в этом фрагменте. Резервная копия исходного файла сохраняется с правами `0600` в `/opt/var/lib/hotwatcher/dns-auto-backup.json`. Ранее существовавшие `hosts`, `tag`, `queryStrategy` и другие поля объекта `dns` сохраняются. JSONC-комментарии в изменяемом файле при включении преобразуются в обычный JSON, а при откате исходные байты восстанавливаются. Если в конфигурации несколько объектов `dns`, есть серверы с отдельными правилами, локальный/FakeDNS-резолвер, маршрутизируемый `dns.tag` или конфликтующая запись `hosts` для DNS-провайдера, команда останавливается без изменения конфигурации. Локальные зоны в таком случае требуют ручной настройки, чтобы не потерять их разрешение.

На роутерах с малым объёмом RAM подготовка и URL Test могут завершиться сообщением о нехватке памяти: Hot Watcher не запускает второй Xray, если это угрожает основному процессу и сети. Повторять проверку без освобождения RAM не нужно.

После записи нужен **один ручной перезапуск XKeen**: Xray не предоставляет Hot Watcher API для изменения DNS-конфигурации на лету. Команда `dns status` показывает содержимое файла, но не подтверждает, что работающий процесс уже загрузил новую DNS-конфигурацию. Hot Watcher не перезапускает XKeen автоматически, чтобы не обрывать текущие соединения.

`dns verify` проверяет текущий DNS-объект через кратковременный Xray на `127.0.0.1`. Для прямого DoH используется один пробный процесс; проверка через выбранный VLESS помечается как неприменимая, потому что `https+local` его обходит. Для маршрутизируемого DNS могут выполняться обе пробы. Команда также проверяет API основного процесса, но **не может доказать по API**, что тот уже загрузил новый DNS-файл. Временная проба не копирует все правила маршрутизации рабочего Xray.

После перезапуска проверьте на своём маршруте работу сайтов и доменов, которые должны идти напрямую и через VPN. При отсутствии работающего прокси маршрутизируемый DNS может мешать разрешению имён. Для проверки того, какие DNS-запросы проходят через Xray, используйте журнал Xray и существующие правила маршрутизации; обычный `nslookup` на роутере обычно проверяет системный DNS, а не встроенный DNS Xray.

## Откат

```sh
/opt/sbin/hotwatcher dns auto off
xkeen -xtest
xkeen -restart
```

Откат доступен и при недоступном Xray API. Если DNS-файл после включения менялся вручную, Hot Watcher откажется его перезаписывать; сначала разберите конфликт, сохранив копию сторонних правок. Резервная копия остаётся на месте до успешного отката. Команда не меняет DNS Keenetic и не удаляет чужие фрагменты Xray.

Документация Xray: [DNS-модуль и параллельные запросы](https://xtls.github.io/en/config/dns), [объединение фрагментов](https://xtls.github.io/en/config/features/multiple.html). Адреса DoH: [Cloudflare](https://developers.cloudflare.com/1.1.1.1/encryption/dns-over-https/make-api-requests/), [Google](https://developers.google.com/speed/public-dns/docs/doh).
