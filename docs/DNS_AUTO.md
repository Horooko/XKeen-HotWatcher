# Автоматический выбор DNS в Xray

`hotwatcher dns auto on` включает в **DNS-модуле Xray** параллельные запросы к двум DoH-провайдерам: Cloudflare (`https+local://1.1.1.1/dns-query`) и Google (`https+local://dns.google/dns-query`). Для каждого запроса Xray принимает первый успешный ответ. Режим `+local` направляет DoH напрямую через Freedom и не допускает петлю через маршрутизатор прокси. Предварительная проверка Hot Watcher трижды запрашивает каждый сервер по HTTPS с прямого маршрута роутера и требует хотя бы два правильных ответа от каждого; затем проверяет подготовленный DNS во временном Xray, прежде чем записать файл. Результат содержит медианную задержку. Провайдеры выбираются по доступности, а не по одному измерению скорости: скорость меняется от запроса к запросу, поэтому выбор ответа делает сам Xray. Yandex, системный, DHCP и нешифрованный DNS не добавляются.

Это **не меняет DNS-настройки Keenetic, DHCP или Karing**. Функция влияет на запросы, которые уже направлены во встроенный DNS Xray. Если устройства используют DNS роутера напрямую, этот режим сам по себе их запросы не перенаправит. Параллельный запрос отправляется обоим провайдерам: это ускоряет выбор ответа, но оба могут видеть запрашиваемое имя. Действующий маршрут Xray для DNS, включая `dns.tag`, сохраняется. Проба `dns test` идёт непосредственно с роутера; её результат не доказывает, что тот же DoH-маршрут будет доступен из Xray через VLESS.

## Включение

В Entware shell вне игровой сессии:

```sh
/opt/sbin/hotwatcher dns status
/opt/sbin/hotwatcher dns test
/opt/sbin/hotwatcher dns auto on
xkeen -xtest
xkeen -restart
xkeen -status
/opt/sbin/hotwatcher dns verify
/opt/sbin/hotwatcher dns status
```

`dns auto on` меняет файл в `/opt/etc/xray/configs` только после успешной проверки **полного набора фрагментов** установленным Xray. Резервная копия исходного файла сохраняется с правами `0600` в `/opt/var/lib/hotwatcher/dns-auto-backup.json`. Ранее существовавшие `hosts`, `tag`, `queryStrategy` и другие поля объекта `dns` сохраняются. JSONC-комментарии в изменяемом файле при включении преобразуются в обычный JSON, а при откате исходные байты восстанавливаются. Если в конфигурации несколько объектов `dns`, есть серверы с отдельными правилами, локальный/FakeDNS-резолвер или конфликтующая запись `hosts` для DNS-провайдера, команда останавливается без изменения конфигурации. Локальные зоны в таком случае требуют ручной настройки, чтобы не потерять их разрешение.

На роутерах с малым объёмом RAM подготовка и URL Test могут завершиться сообщением о нехватке памяти: Hot Watcher не запускает второй Xray, если это угрожает основному процессу и сети. Повторять проверку без освобождения RAM не нужно.

После записи нужен **один ручной перезапуск XKeen**: Xray не предоставляет Hot Watcher API для изменения DNS-конфигурации на лету. Команда `dns status` показывает содержимое файла, но не подтверждает, что работающий процесс уже загрузил новую DNS-конфигурацию. Hot Watcher не перезапускает XKeen автоматически, чтобы не обрывать текущие соединения.

`dns verify` запускает два кратковременных Xray только на `127.0.0.1`: с текущим DNS-объектом напрямую и через сохранённый выбранный VLESS. DNS-запрос к встроенному модулю проходит через диагностический DNS outbound. Команда также проверяет API основного процесса, но **не может доказать по API**, что тот уже загрузил новый DNS-файл. Временная проба не копирует все правила маршрутизации рабочего Xray; результаты двух возможных выходов показаны отдельно. Для проверки конкретного маршрута `dns.tag` и сетевых правил сравните его с рабочей конфигурацией.

После перезапуска проверьте на своём маршруте работу сайтов и доменов, которые должны идти напрямую и через VPN. Если установлен `dns.tag` с маршрутизацией запросов через VLESS, проверка прямого маршрута в `dns test` не проверяет этот путь. При отсутствии работающего прокси такой маршрут может мешать разрешению имён. Для проверки того, какие DNS-запросы проходят через Xray, используйте журнал Xray и существующие правила маршрутизации; обычный `nslookup` на роутере обычно проверяет системный DNS, а не встроенный DNS Xray.

## Откат

```sh
/opt/sbin/hotwatcher dns auto off
xkeen -xtest
xkeen -restart
```

Откат доступен и при недоступном Xray API. Если DNS-файл после включения менялся вручную, Hot Watcher откажется его перезаписывать; сначала разберите конфликт, сохранив копию сторонних правок. Резервная копия остаётся на месте до успешного отката. Команда не меняет DNS Keenetic и не удаляет чужие фрагменты Xray.

Документация Xray: [DNS-модуль и параллельные запросы](https://xtls.github.io/en/config/dns), [объединение фрагментов](https://xtls.github.io/en/config/features/multiple.html). Адреса DoH: [Cloudflare](https://developers.cloudflare.com/1.1.1.1/encryption/dns-over-https/make-api-requests/), [Google](https://developers.google.com/speed/public-dns/docs/doh).
