# Тестирование

## Автоматические тесты без роутера

```sh
go test -race -cover ./...
go vet ./...
```

Покрываются конвертер URI/Base64, семантические теги, ротация UUID, пропуск не-VLESS,
отклонение пустого/битого/слишком большого ответа, HTTPS/redirect policy, приватные
файлы, блокировка, миграция, неизменившаяся подписка, hold, отказ probes/API, промежуточная
ошибка записи state, recover/abort, retired/GC, ownership/hash checks, разбор CLI API.

Процессные тесты используют **специальный fake-Xray subprocess**. Это проверяет передачу
аргументов/stdin, очистку окружения, capture/redaction и жизненный цикл test-процесса,
но не доказывает совместимость с реальным Xray. Это различие отражено в TEST_REPORT.md.

## Дополнительный тест с настоящим Xray

Нужен Go и официальный Xray для архитектуры тестовой машины:

```sh
XRAY_INTEGRATION_BINARY=/absolute/path/to/xray go test -v ./internal/hotwatcher -run TestRealXrayHotAPIPreservesEstablishedTCP
```

Тест создаёт отдельный loopback Xray, HTTP CONNECT до локального echo-сервера и проверяет:
`ado -> lso -> bo -> bi -> rmo`, а также продолжение ранее установленного TCP-соединения.
Тестовые outbounds — локальные `freedom`, чтобы отделить API/session lifecycle от реального
провайдера. Этот smoke-test **не проверяет VLESS+Reality или игровой UDP**.

Без переменной тест отмечается `SKIP`, а не «успешно проверено на настоящем Xray».
Не запускай его с бинарником другой архитектуры. В поставляемой среде реальный Xray
не был доступен; см. точный статус в отчёте.

## Приёмка на целевом роутере

Проводить сначала вне активной игры, с доступом к локальной консоли/SFTP и backup.

1. `doctor`: рабочий localhost API и нужный balancer. `plan`: ожидаемое число узлов,
   никакого дампа UUID/URL. `adopt`: проверка candidate и запись private backup.
2. Снять основной PID после завершения тестовых дочерних процессов. Изменить отдельный
   тестовый UUID на стороне сервера, **не отзывать предыдущий ключ мгновенно**.
3. `sync`: проверить `applied`, новый selected tag, прежний основной PID, наличие retired,
   совпадение файла/state. Проверить доступность реального сервиса.
4. Дать службе выполнить несколько периодов без изменений: не должно быть `ado`/смены
   selected из-за одного имени или порядка строк. Проверить восстановление pin после
   планового рестарта отдельно, вне игры.
5. Отдать пустую подписку/HTML/403/битый VLESS. `sync` должен завершиться ошибкой и оставить
   прежние target, file hash и рабочий процесс.
6. Закрыть доступ к одному новому candidate. Он должен остаться в списке ключей,
   но не стать выбранным маршрутом, пока другой ключ проходит HTTPS-проверку.
7. Проверить длительное TCP и **отдельно UDP/Destiny 2** при ротации ключа на том же сервере
   и при смене сервера. Не подменять эти две проверки друг другом.
8. Проверить hold: fetch/применение/GC не выполняются, сохранённый pin восстанавливается.
9. Вне игры вызвать `gc` после grace: удаляются только собственные retired, не direct,
   block, static vless-reality или legacy outbounds первой миграции.
10. Отдельно проверить fail-closed политику IPv4/IPv6 при остановленном Xray. Сам Hot Watcher
    этого теста не проходит и не должен изображаться как kill-switch.

## Отказы и процесс

Не тестируй kill -9 рабочего Xray в активной игре. Fault-injection транзакций покрывается
тестами с fake runtime; hardware power-loss, состояние SD/USB/NAS после потери питания,
особенности файловой системы и ядра Keenetic требуют отдельного стенда.

После SIGKILL самого Hot Watcher его test-child при некоторых сценариях может остаться
до завершения/таймаута. Это не основной Xray и не netfilter-service. Не используй
`killall xray`: он убьёт и основной клиент. Разбирай конкретные PID/command line.
