# Статический маршрут и проверка активного ключа

В версии 0.2.7 команда `hotwatcher check-key` проверяет активный ключ двумя
HTTPS-запросами через отдельные Xray-процессы. Если обе пробы не проходят,
измеряет остальные сохранённые узлы и закрепляет самый быстрый проверенный.
Загрузка подписки для этой команды не требуется. Если ни один узел не ответил,
старый маршрут сохраняется и команда возвращает ошибку. Служба выполняет ту же
проверку каждые 300 секунд (`key_check_interval_seconds`), в том числе после
неудачной загрузки подписки. `hold on` приостанавливает такие переключения.

Точный заголовок узла из `keys` можно передать команде `select`:

```sh
hotwatcher select "VL HLVPN_09-12FIN_2_UNDEF"
hotwatcher check-key
hotwatcher keys
```

Имя должно совпадать целиком. Имя с пробелами лучше заключать в кавычки;
несколько аргументов после `select` также объединяются пробелами. Если два ключа
имеют одно имя, используется только тег из `keys`. `select` повторно проверяет
кандидата и доступность рабочего Xray API перед сохранением транзакции.
Остановка Xray между этой проверкой и API-переключением всё ещё может оставить
`pending.json`; после запуска Xray используй `hotwatcher recover` или, если
восстановление не проходит, штатный `abort` по [инструкции](ROLLBACK.md).

Для возврата к статическому VLESS-ключу из существующего
`/opt/etc/xray/configs/04_outbounds.json`:

Перед `stop` Xray должен работать и Hot Watcher должен иметь завершённую
миграцию (`adopt`) без `pending.json`. Если Xray остановлен, сначала выполни
`xkeen -xtest` и `xkeen -start`; если есть pending-транзакция, после запуска
Xray заверши её через `hotwatcher recover` или штатный `abort`.

```sh
hotwatcher status
hotwatcher stop
hotwatcher status
```

`stop` снимает маркер автозапуска и останавливает только службу Hot Watcher.
Затем он берёт outbound с тегом `vless-reality` из старого файла (тег можно
задать через `static_fallback_tag`), проверяет полный конфиг Xray и успешный
HTTPS-запрос через этот ключ. После проверки в управляемом
`04_outbounds.main.json` остаётся только его копия с тегом
`main--VL--hw-static-fallback`, соответствующим текущему селектору
балансировщика. Рабочий Xray переключается на этот тег через API без рестарта.
`04_outbounds.json`, маршруты `05_routing.json`, firewall и текущий Xray PID не
изменяются. При следующем запуске Xray статическая копия снова будет загружена.
Автоустановка программы временно ставится на паузу; если пауза уже была включена
администратором, она сохраняется при возврате.

Если статический ключ не проходит HTTPS-пробу, `stop` **не** переводит маршрут
на него. При отказе после записи маркера `static-mode.json` Hot Watcher остаётся
выключенным; выполни `hotwatcher start` для завершения/отката перехода после
восстановления Xray API. Не удаляй маркер или файлы состояния вручную.

Чтобы вернуть ключи подписки:

```sh
hotwatcher start
hotwatcher status
hotwatcher keys
```

`start` проверяет узлы из сохранённого состояния и полный Xray-конфиг. Если ни
один ключ подписки не отвечает, статический маршрут сохраняется, а служба
остаётся выключенной. При успехе `start` выбирает самый быстрый работающий
ключ, восстанавливает управляемый файл и запускает службу. Весь переход не
запускает `xkeen` и не перезапускает основной Xray. Если Xray выключен, сначала
запусти его штатно (`xkeen -xtest`, затем `xkeen -start`): в статическом режиме
он загрузит сохранённую копию старого ключа.

`/opt/etc/init.d/S99hotwatcher start|stop` остаются командами управления только
процессом службы. Updater использует их при установке новой программы. Для
смены маршрута используй именно `hotwatcher start|stop`.

Удалять `04_outbounds.main.json` нельзя: при работающем режиме он содержит
узлы подписки, а в статическом режиме — копию старого ключа с тегом, который
видит балансировщик `proxy`. Исходный `04_outbounds.json` тоже нужен: из него
берётся статический ключ. Оригинальный файл прежней подписки сохранён в
`/opt/var/lib/hotwatcher/pre-migration-outbounds.json` для отдельного полного
отката; это другая операция.
