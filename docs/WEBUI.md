# Web UI и URL Test

Web UI запускается вместе с включённой службой Hot Watcher. Она встроена в тот же
бинарник: отдельный Node.js, база данных, CDN или дополнительный демон не нужны.
По умолчанию панель слушает только `127.0.0.1:8787` на роутере.

## Вход с компьютера

В Entware shell роутера узнайте токен:

```sh
/opt/sbin/hotwatcher webui token
```

На компьютере откройте SSH-туннель, подставив адрес роутера:

```sh
ssh -L 8787:127.0.0.1:8787 root@192.168.1.1
```

Откройте `http://127.0.0.1:8787` и вставьте токен. Токен хранится в
`/opt/var/lib/hotwatcher/webui-token` с правами `0600`. Не публикуйте его и не
передавайте через URL. Сессия браузера действует 12 часов. Панель проверяет
локальный Host, использует cookie `HttpOnly` и защищает изменяющие запросы от CSRF.

Для прямого доступа из доверенной локальной сети можно явно указать IP роутера в
`webui_listen`, например `192.168.1.1:8787`, и перезапустить только службу
Hot Watcher. Встроенный HTTP не шифрует токен при передаче по LAN, поэтому для
обычного использования рекомендуется SSH-туннель. Публичный адрес и `0.0.0.0`
не принимаются. `webui_enabled: false` отключает панель.

## Страницы панели

- **Обзор:** состояние Xray, выбранный ключ и быстрые действия.
- **Ключи:** сохранённые и последние загруженные ключи, быстрый выбор,
  закрепление и возврат в авто; форма аварийного VLESS-ключа.
- **URL Test:** проверка выбранного или другого применённого ключа и редактор
  обязательных сайтов. Сохранение списка действует сразу, без перезапуска.
- **Система:** вывод `xkeen -status`, последние строки
  `/opt/var/log/xkeen-detached.log` и `/opt/var/log/xray/error.log`, состояние
  конфигурации и восстановления. URI, URL и UUID в показанных строках скрываются.
- **Обновления:** установленная и доступная версия, результат предыдущей
  установки, выбор политики `patch`/`minor`, кнопки проверки и установки
  подписанного релиза.

При переходе остаётся виден только выбранный раздел.

`hard-sync`, который временно выключает XKeen, остаётся командой терминала: панель
его не запускает. При ошибке синхронизации старый выбор сохраняется.

## Выбор и аварийный ключ

«Выбрать» в таблице ключей проверяет URL Test и переключает новые соединения.
«Закрепить» переводит Hot Watcher в ручной режим. В этом режиме фоновая проверка
сообщает об ошибке, но не сменит ключ, а синхронизация сохранит его даже при
исчезновении из подписки. «Включить автовыбор» снимает закрепление и сразу
проверяет доступные ключи по задержке и обязательным сайтам.

В форму аварийного ключа вставьте **один** исходный `vless://` URI. Hot Watcher
проверяет формат и конфигурацию Xray, добавляет outbound без перезапуска Xray,
выбирает его и закрепляет. Это явная аварийная команда: она может применить ключ
даже при неудачном URL Test; предупреждение видно в панели. Старый outbound
остаётся доступен для возврата. Исходный URI не сохраняется целиком и не
возвращается через API; приватное состояние содержит необходимые параметры
разобранного outbound. Не передавайте URI в чат, issue или логи.

Аналогичные команды терминала: `hotwatcher pin ИМЯ`, `hotwatcher auto` и
`hotwatcher emergency` (последняя читает URI из стандартного ввода, чтобы он не
попал в историю команд).

## Обновления

Страница использует существующий updater с проверкой подписи и хеша. Для
перехода с 0.2.x на 0.3.0 нужна политика `minor`; выбор сохраняет режим
уведомлений или автоустановки. Если обновления выключены, кнопка «Включить
обновления» запускает режим уведомлений. Кнопка «Проверить обновления» запрашивает
подходящий подписанный релиз, а «Установить» запускает отдельный процесс
обновлятора. Он может перезапустить службу Hot Watcher и Web UI; после этого
войдите снова и посмотрите результат на странице обновлений. XKeen и Xray
установщик не перезапускает. При сбое применяется существующий автоматический
откат updater.

## Правила URL Test

По умолчанию обязательны `google.com`, `chatgpt.com`, `youtube.com`,
`discord.com`, `telegram.org` и `github.com`. Редактор принимает от 1 до 12
публичных HTTPS-доменов без пути, параметров и нестандартного порта. Пустой
список не допускается. Настройка из Web UI хранится в приватном
`state_dir/url-test-sites.json` и имеет приоритет над `url_test_sites` в основном
конфиге. При отсутствии этого файла действует список из основного конфига.

Сначала выполняется короткая проверка HTTPS 204 для оценки задержки ключей.
Перед переключением выбранный кандидат проходит URL Test: временный Xray на
`127.0.0.1` отправляет HTTPS GET ко всем обязательным сайтам через этот ключ.
Разрешены до трёх перенаправлений в пределах того же домена или его `www`-имени;
успехом считается итоговый HTTP 2xx. Ошибка TLS, таймаут, HTTP 403/5xx или
недоступность хотя бы одного сайта отклоняют ключ. Тогда проверяется следующий
кандидат. Если никто не прошёл, рабочий выбор не меняется. Исключение — явно
запрошенное аварийное применение или закрепление: эти действия доступны при
ошибках сетевых проверок и оставляют выбор под ручным контролем.

Сайты проверяются по три одновременно, чтобы один таймаут не задерживал все
остальные. URL Test подтверждает HTTP-ответ главной страницы, но не проверяет
JavaScript, вход в аккаунт, видео или голосовые соединения. Результат зависит
от ограничений сайтов для IP конкретного прокси. Отдельная команда:

```sh
/opt/sbin/hotwatcher url-test
/opt/sbin/hotwatcher url-test ТЕГ_КЛЮЧА
```
